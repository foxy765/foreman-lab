# Тестовое задание Foreman

В этом задании я настроил Foreman, установил через него
AlmaLinux на вторую виртуальную машину и применил Ansible-роль,
которая запрещает вход по SSH под root.

## Что использовал

Работу выполнял на Windows 11 в VirtualBox.
Создал две виртуальные машины:

- foreman.lab.test — сервер Foreman, адрес 192.168.56.10.
- managed01.lab.test — хост под управлением Foreman,
  адрес 192.168.56.118.

На обеих машинах используется AlmaLinux 9.8.

У каждой машины два сетевых адаптера:
Host-only для связи между машинами и NAT для доступа в интернет.

Встроенный DHCP VirtualBox отключил, чтобы адреса
в сети Host-only выдавал сервер, настроенный через Foreman.

## Что сделал

1. Установил Foreman 5.0.1 и подключил Ansible.
2. Настроил DNS, DHCP и TFTP для установки ОС по сети.
3. Добавил в Foreman домен lab.test и подсеть lab-network.
4. Создал группу хостов AlmaLinux9-NTP.
5. Подготовил шаблоны сетевой загрузки и установки ОС
   на основе стандартных шаблонов Foreman.
6. Добавил managed01.lab.test в созданную группу
   и установил на него AlmaLinux по сети.
7. Через шаблон установки настроил синхронизацию времени.
8. Создал Ansible-роль disable_root_ssh, назначил её группе
   хостов и запустил из интерфейса Foreman.

## Файлы

- templates/almalinux-kickstart-ntp.erb —
  шаблон установки AlmaLinux с настройкой времени.
- templates/almalinux-pxelinux-nat.erb —
  шаблон для загрузки установщика по сети.
- ansible/roles/disable_root_ssh/tasks/main.yml —
  действия Ansible-роли.
- ansible/roles/disable_root_ssh/handlers/main.yml —
  перечитывание настроек SSH после изменения файла.
- docs/screenshots/ — скриншоты настроек и результата.

Шаблоны используют готовые части стандартных шаблонов Foreman.
Их нужно импортировать в Foreman, отдельно они не выполняются.

## Настройка времени

Для синхронизации времени используется chrony.
В группе хостов указан сервер time.cloudflare.com.

После установки ОС проверил, что служба chronyd работает
и время синхронизируется.

## Запрет входа root по SSH

Для подключения Ansible создал на managed01 пользователя
ansible и добавил ему SSH-ключ Foreman Proxy.
Для выполнения настроек разрешил sudo без пароля.

Роль disable_root_ssh добавляет в начало файла
/etc/ssh/sshd_config настройку:

PermitRootLogin no

Перед сохранением проверяется правильность конфигурации.
Если файл изменился, служба sshd перечитывает настройки.

Это запрещает прямое подключение по SSH под root.
Вход под обычным пользователем и использование sudo остаются.

## Как проверял

- Виртуальная машина загрузилась с установленной AlmaLinux.
- Проверил имя машины и её IP-адреса.
- Проверил работу chronyd и синхронизацию времени.
- Запустил Ansible-роль из Foreman — задание прошло без ошибок.
- Команда sshd -T показала permitrootlogin no.
- Повторно запустил роль: ошибок нет, changed=0.
  Это означает, что повторный запуск не внёс новых изменений.

## Чем Foreman отличается от ручной настройки

При ручном подходе с Docker, Nginx и Samba можно запустить
нужные сервисы и организовать раздачу установочных файлов.
Но учёт машин, параметры установки и последующую настройку
нужно организовывать отдельно.

В Foreman можно хранить список хостов, объединять их в группы,
задавать параметры установки ОС и запускать Ansible-роли.

Для меня основной плюс — возможность задать общие настройки
для группы машин и повторно использовать их.

Основной минус — сложность первоначальной настройки.
Нужно разобраться со связью между Foreman, сетью,
шаблонами установки и Ansible.
Для нескольких машин ручная настройка может быть проще.

## Ограничения и возникшие сложности

Это локальный учебный стенд в VirtualBox.

В шаблонах используются IP-адреса, имена сетевых интерфейсов
и MAC-адрес моего стенда. Для другой сети их нужно изменить.

Пользователю ansible разрешён sudo без пароля.
Для рабочей системы права нужно настроить с учётом её требований.

После установки ОС Foreman оставался в режиме Build.
Причину автоматического завершения этого режима до конца
не выяснил, поэтому выключил его вручную.
В VirtualBox поставил загрузку с диска на первое место.

Также возникли проблемы со скачиванием файлов через мою сеть
с Podkop. Для repo.almalinux.org временно добавил исключение
проверки DNSSEC на DNS-сервере стенда.

Настройки Foreman выполнял через веб-интерфейс.
В репозитории сохранены шаблоны и Ansible-роль,
но полное автоматическое создание стенда не реализовано.
